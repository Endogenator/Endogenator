## Connective Tissue

Every new AI conversation starts from nothing. Connective Tissue is how I keep dozens of sessions across separate projects consistent over months when none of them remembers the others. Each area of work has one canonical document, an anchor, that any session can read and only one project can change. It links chats and projects so they move together.

Status label: **In daily use**

**How a change moves through the system**

1. **Read.** Every session starts by reading the current anchor for its area of work.
2. **Propose.** A session with something new files a supplement. It never edits the anchor.
3. **Reconcile.** The owning project gathers supplements and works through them with me. Nothing gets folded in silently.
4. **Replace.** The result is written as a full replacement, so the anchor always reads as one coherent document.
5. **Apply.** A script swaps the replacement in and archives everything it consumed. No AI session touches this step.

**Design decisions**

- **One owner per area.** Every session can read any anchor. Only its owning project can change it.
- **Proposals first.** Contributions arrive as separate files, the way code arrives as a pull request.
- **A person rules.** AI proposes. I decide what becomes settled.
- **Status is explicit.** Every term is proposed, working, settled or retired, and the record shows which.
- **History kept.** Retired ideas and superseded versions are archived, so later sessions know what was tried and dropped.
- **One place per fact.** Each fact lives in one place. Everything else refers to it.
- **Self-governing.** The protocol that runs the system has its own path for changing itself.

Why I built it, and what it does and doesn't fix, is in [Why I Built This](https://generative.endogenator.com/applications/agency-in-the-age-of-ai).
